EasyPDV: self-checkout retail platform

EasyPDV runs autonomous mini-markets in condominiums and offices. Shoppers scan and pay at a kiosk (PIX or card) with no staff in the store. Behind it are a cloud ERP, warehouse operations and a mobile app for the people who restock the stores. It also powers Despensinha, an autonomous-market network in Northeast Brazil.

The code is my employer's and stays private. These case studies describe what I built and why, without code.

Operator app: warehouse and store operations

Main developer · ~700 of ~900 commits · Nov 2025 – now · Google Play

Operators separate orders, restock shelves, count inventory and check supplier deliveries, all from their phone or a handheld scanner. I've led the app from early on, on Android and iOS.

What I built

  • Picklists and restocking: create picklists per store and category, track separation, and restock with one tap per item or a "restock all".
  • Inventory: scheduled and on-demand counts, plus product bundles (combos).
  • Barcode scanning: a continuous camera scanner (CameraX + ML Kit) built into the inventory, separation and supply screens, with fixes for handheld scanners.
  • Damage photos: camera capture, a local image store and a background uploader, so a weak connection never loses a photo. Shipped as a six-part stack of PRs.
  • Goods receipt: check a supplier invoice item by item, with saving that holds up on a bad connection, then complete the receipt.
  • Release pipeline: automated versioning, Google Play upload, and iOS signing and IPA export in GitHub Actions.
  • Firebase push notifications, sessions that renew tokens on their own, and features gated by account permissions.

Engineering

  • Moved the screens to an MVI architecture with dependency injection, which made them testable and predictable.
  • Quality gates: detekt, Konsist architecture rules, Kover coverage and SonarQube. Tests run on Robolectric and Turbine.

Sales risk analysis: catching theft at self-checkout

Designed and built end to end · Java API + React UI · Oct 2026

With no cashier present, losses show up as patterns in the data. I built a system that scores every self-checkout sale for suspicious behaviour, so managers can review the risky ones.

What I built

  • Pluggable detectors, each with its own switch and weight: runs of cheap scans, long gaps between scans, abandoned sales, failed payments, items removed from the cart, risky hours, and watched products.
  • Sales are evaluated as they arrive from the kiosk. Bulk re-evaluation runs as a background job, with context loaded in batches to avoid N+1 queries.
  • A "most lost products" ranking that feeds the watch list.
  • In the admin: a suspicion card on each order, filters, per-signal settings with points and decay, and one-click "open an incident" with the sale pre-filled.

Engineering

  • Shipped as a chain of five reviewable PRs: config, watched products, evaluation, batch evaluation, listing.
  • About 20 test classes covering unit, persistence and controller tests.

Announcements: required reading with read receipts

Designed and built end to end · Java API + React UI · Oct 2026

Operators work spread across many sites, and the company needed a way to make sure they actually read important notices.

  • Full lifecycle: draft, publish, effective period, close. Targeting by recipient and role.
  • A rich-text editor (TipTap) with images, MP4/WebM video and YouTube embeds, with media stored in S3. Files are deleted only after the database transaction commits.
  • "Seen", "acknowledged" and "dismissed" states, an inbox shown at login, a real-time notification bell, and an acknowledgement report.
  • Receipts and bell entries are reserved atomically, and an integration test proves that under concurrency.
  • Queries use JPA Specifications instead of native SQL.

Nexus: syncing data from third-party systems

Main developer · ~97% of commits · Sep – Oct 2026

New customers arrive with their catalogue, stores and planograms in other systems. Nexus is a reconciliation service that brings that data into EasyPDV safely.

  • Connector-based design: each external system plugs in as its own connector.
  • Sync runs compute a diff, and someone must approve it before anything is overwritten, item by item.
  • Products missing from a planogram are created in bulk. Retries and skips are counted, failures get reason codes, and every run produces an operation report.
  • An import wizard in the admin web app, with conflict resolution, server-side paging and progress streamed over SSE.
